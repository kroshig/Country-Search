# DESIGN.md — Архитектура и проектные решения Country Search

## 1. Механизм отмены устаревших запросов (`AbortController`)

### Как устроена отмена

1. В `SearchController` (`src/core/searchController.ts`) хранится ссылка на `currentAbortController` активного сетевого запроса.
2. **Немедленная отмена при вводе:** В методе `handleInput()` вызов `this.abortActiveRequest()` происходит **в самом начале обработчика каждого события ввода**, ещё до того, как истечёт таймер `debounce` для нового текста. Если бы отмена вызывалась только внутри колбэка `debounce`, то за 300 мс ожидания старый запрос мог бы завершиться и отрисовать устаревшие карточки под уже изменённым текстом в поле ввода.
3. **Композиция сигналов (`AbortSignal.any`):** Функция `searchCountries(query, signal)` принимает пользовательский `AbortSignal` и объединяет его с `AbortSignal.timeout(8000)` через `AbortSignal.any([userSignal, timeoutSignal])`. В `catch` ошибки различаются по `error.name`:
   - `'AbortError'` — штатная отмена пользователем (`isSilent: true`), UI не показывает ошибку;
   - `'TimeoutError'` — истечение времени ожидания сервера (`isSilent: false`), UI показывает сообщение об ошибке с кнопкой «Повторить».

### Почему `AbortController`, а не булев флаг или сверка `requestId`

Подход с флагом (`let latestRequestId = ...`) лишь игнорирует результат в JS-коде после того, как браузер уже скачал тело ответа:

- **Экономия трафика и CPU:** Настоящий `controller.abort()` разрывает HTTP-соединение на уровне браузера (запрос переходит в статус `canceled` в DevTools Network), предотвращая бесполезную загрузку и парсинг JSON (`response.json()`).
- **Освобождение сокетов:** При медленном соединении (3G / Throttling) неотменённые «висящие» запросы забивают пул одновременных соединений браузера к домену и задерживают отправку актуального запроса.

## 2. Обоснование задержки `debounce` (300 мс)

В проекте выбрана задержка **300 мс**:

- Средняя скорость набора текста составляет 150–250 мс между нажатиями клавиш. Задержка 300 мс позволяет пользователю набрать слово целиком (например, `s-p-a-i-n`) и отправить всего **один** сетевой запрос вместо пяти.
- **Что будет, если убрать `debounce` (0 мс):** Каждое нажатие клавиши будет инициировать TCP/TLS-рукопожатие и HTTP-запрос к `countries.dev`, которые тут же будут отменяться следующей буквой. Это создаст лишнюю нагрузку на API, приведёт к риску получить `429 Too Many Requests` и вызовет постоянное мерцание индикатора загрузки.
- **Что будет, если сильно увеличить задержку (1000+ мс):** Интерфейс начнёт восприниматься как «зависший» — после окончания ввода пользователь будет секунду смотреть на пустой экран без индикатора загрузки, что нарушает паттерн отзывчивого живого поиска (Порог Доэрти — до 400 мс).

## 3. Оценка сложности (Big O)

### `mapCountryResponse(raw)` (`src/mappers/mapCountry.ts`)

Для одной страны из ответа API:

- **Временная сложность:** $O(L + C + B)$, где $L$ — количество языков страны, $C$ — количество валют, $B$ — количество граничащих стран. Поскольку у любой реальной страны $L, C, B$ ограничены малыми константами (обычно $\le 15$), амортизированная сложность преобразования одной карточки составляет **$O(1)$**. Для массива из $N$ найденных стран сложность равна **$O(N)$**.
- **Пространственная сложность:** **$O(L + C + B)$** (или **$O(1)$** на одну карточку и **$O(N)$** на список из $N$ стран), так как создаётся новый иммутабельный объект `Country` с копиями массивов строк.

### Кэш и дедупликация запросов (`CachedCountryClient` в `src/core/cacheClient.ts`)

- **Поиск в кэше (`Map.get`) и проверка активных запросов (`inFlight.get`):** Временная сложность **$O(K)$** на нормализацию (`trim().toLowerCase()`) и хеширование строки запроса длины $K$, и **$O(1)$** на чтение из хеш-таблицы `Map`.
- **Пространственная сложность кэша:** **$O(U \cdot M)$**, где $U$ — уникальные поисковые запросы за сессию, а $M$ — среднее число стран в ответе.

## 4. Применённые принципы чистого кода

1. **Single Responsibility Principle (SRP):**
   - `src/api/searchCountries.ts` отвечает исключительно за транспортный уровень HTTP и компоновку `AbortSignal`.
   - `src/mappers/mapCountry.ts` (`mapCountryResponse`) отвечает только за трансформацию сырого JSON в доменную модель.
   - `src/errors/httpError.ts` (`classifySearchError`) изолирует правила интерпретации ошибок (`AbortError` vs `TimeoutError` vs `HttpError`).
   - `src/ui/domView.ts` (`CountrySearchView`) отвечает только за построение DOM-узлов и не знает о `fetch` или таймерах.
2. **Чистые функции (Pure Functions) и детерминированность:**
   - `mapCountryResponse` и `classifySearchError` не имеют побочных эффектов, не мутируют входные аргументы и тестируются без моков сети или DOM.
3. **Dependency Inversion / Dependency Injection:**
   - `SearchController` и `CachedCountryClient` принимают функцию загрузки `fetcher: FetcherFn` через конструктор, что позволяет тестировать контроллер и гонки запросов без браузера и с контролируемыми задержками.
4. **Безопасная работа с DOM:**
   - В `src/ui/domView.ts` полностью исключено использование `innerHTML` и `insertAdjacentHTML`. Все элементы создаются через `document.createElement`, а текст вставляется через `textContent`, что исключает XSS-уязвимости.
